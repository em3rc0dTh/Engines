## Core architecture rule

**Engines comes first. CTA is independent and replaceable.**

```text
CLI ───────────┐

WebChat ───────┤
```

```text

```


## WhatsApp result

The synthetic inbound request was HMAC verified before `WhatsAppAdapter` execution. At Workflow start:

```text

missingFields = name, email
```

The Workflow therefore requested only name and email and reached:

```text
COMPLETED / CREATED

```

If the lab ever renders a WhatsApp phone question after accepted sender-phone prefill, the automated proof fails.

## Official-provider boundary

No real provider has been certified by this local gate.

WhatsApp remains official-route-only. Browser automation, WhatsApp Web session emulation, QR-session scraping and reverse-engineered clients remain rejected.

Meta Cloud API versus Kapso is still a provider implementation choice behind `WhatsAppTransportPort`.

Telegram real proof will use the official Telegram Bot API later.

## Current Step-3 truth

Services S7 remains certified on `build/mk1-s7-appointment-services-integration`. Appointment consumes canonical Services reads and freezes revision-aware Service/Offering selection state. Scheduler authority remains separate.
