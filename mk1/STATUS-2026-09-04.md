## C2P — official Telegram Bot API

C2P is the first gate that connects the channel stack to a real external messaging-provider API.

Architecture:

```text
real Telegram user
  ↓
Telegram Bot API official HTTPS
  ↓
getUpdates long polling
  ↓
TelegramAdapter
  ↓
CanonicalChannelEnvelope
  ↓
CustomerRegistrationChannelExecutionCore
  ↓
PostgreSQL durable channel ledger
  ↓
Temporal RegisterNewCustomer
  ↓
Customer persistence
```

The runtime contains an official Bot API HTTP client and a local long-poll runner. It uses only Bot API methods required for this physical slice: `getMe`, `getWebhookInfo`, `getUpdates`, `sendMessage` and `answerCallbackQuery`.

The runner fails closed if another webhook deployment is active, keeps `businessSlug` in trusted deployment configuration, never logs the bot token and rejects a shared contact whose Telegram `user_id` conflicts with the actual message sender.

## Official-provider boundary

Telegram C2P uses only the official Bot API. WhatsApp remains official-route-only; browser automation, WhatsApp Web session emulation, QR-session scraping and reverse-engineered clients remain rejected.

Meta Cloud API versus Kapso remains a future WhatsApp provider implementation choice below `WhatsAppTransportPort`.
