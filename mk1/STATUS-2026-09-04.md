## Customer registration policy

The first Telegram/WhatsApp business slice remains intentionally limited to `RegisterNewCustomer` with V2 minimum:

```text
customer.name
customer.contact.phone
customer.contact.email
```

That requirement lives in Customer/Temporal policy, never in provider code.

## Telegram Web client boundary

The patched renderer emits an official private-chat `ReplyKeyboardMarkup` with `request_contact=true`, `is_persistent=true` and a typed-phone fallback. Telegram Web displayed the hardened prompt text but did not visibly render the native `Compartir teléfono` reply-keyboard button.

This does not reopen C2P because typed phone is an explicit supported registration path and the full real-provider/Engine chain completed physically. Native contact rendering is client-specific and remains an optional Mobile/Desktop compatibility observation.

Official references:

- https://core.telegram.org/bots/api#keyboardbutton
- https://core.telegram.org/type/KeyboardButton
- https://bugs.telegram.org/c/11527/1
