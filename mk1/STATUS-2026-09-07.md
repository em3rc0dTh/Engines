## Kapso decision

Use Kapso Sandbox for the first physical WhatsApp proof because it supports real text + interactive messages and phone-number webhooks without consuming production-number capacity. The dedicated-number path remains separate.

Architecture:

```text
WhatsApp user
→ Kapso Sandbox
→ signed v2 webhook
→ OfficialKapsoTransport
→ WhatsAppAdapter
→ ChannelExecutionCore
→ PostgreSQL durable channel ledger
→ Temporal RegisterNewCustomer
→ Customer persistence
→ Kapso WhatsApp API reply
```

## Identity hardening

`senderPhone` is now optional at the provider-neutral WhatsApp boundary. Verified phone identity may prefill Customer phone after consent. BSUID-only events remain valid and do not invent phone data; outbound replies can address BSUID through provider `recipient` semantics.
